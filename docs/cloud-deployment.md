# Размещение демонстрации

Сайт и Node API работают на Vercel. Речь вынесена в отдельный CPU-контейнер. GigaChat вызывается сервером Vercel: Authorization key не передаётся браузеру и не попадает в образ речи. Компьютер автора после развёртывания не участвует в обработке запросов.

## Контейнер речи

1. Ознакомьтесь с лицензиями весов, в частности с условиями некоммерческого профиля Silero, указанными в README.
2. Выполните `node agent/prepare-cloud-voice.mjs`. В `runtime/cloud-voice` появится Docker-контекст, без ключей и пользовательских дел.
3. Создайте Docker Studio в ModelScope с бесплатным CPU 2 vCPU / 16 GB. Загрузите содержимое этой папки в корень Studio. Порт — 7860. Если бесплатный ресурс недоступен, не выбирайте платный автоматически.
4. В Secrets задайте случайный `QWEN_VOICE_KEY` длиной минимум 32 символа. Код сервиса закрыт, приложение доступно извне; OAuth платформы выключен, серверные запросы защищены своим ключом.
5. Дождитесь сборки и готовности `/asr/health` и `/tts/health`. Образ скачивает точные веса из манифеста и проверяет размер и SHA-256. Несовпадение останавливает сборку.

Распознавание разговора, диктовка и озвучка сохраняют модели текущего локального профиля. Linux-совместимость и задержки требуют реального прогона на выбранном хосте. Наличие Dockerfile само по себе не доказывает работу голоса.

## Vercel

Версия Node.js — 24.x. Framework — Vite. Корневой `vercel.json` задаёт API и маршруты приложения. В переменных окружения, отдельно для Preview и Production, нужны:

| Переменная | Значение |
| --- | --- |
| `CONTOUR_LLM_BACKEND` | `gigachat` |
| `GIGACHAT_MODEL` | `GigaChat-3-Ultra` |
| `GIGACHAT_AUTH_KEY` | Authorization key владельца демонстрации, Secret |
| `GIGACHAT_CA_PEM` | Официальный CA Сбера, PEM; TLS проверяется |
| `QWEN_ASR_URL` | HTTPS-адрес приложения Studio с суффиксом `/asr` |
| `QWEN_TTS_URL` | Тот же адрес с суффиксом `/tts` |
| `QWEN_VOICE_KEY` | Такой же Secret, как в Studio |
| `CONTOUR_REMOTE_TTS` | `silero` |
| `CONTOUR_VOICE_STREAM` | `1` для контейнера с `/tts/speak-stream` |
| `CONTOUR_PUBLIC_DEMO` | `1` |
| `CONTOUR_SESSION_SECRET` | Случайный секрет минимум 32 символа для подписи сеансов |

Проверяющему эти настройки не нужны. Владелец настраивает их один раз на сервере. При открытии страницы сервер устанавливает подписанную HttpOnly-cookie на сутки. Изменяющие запросы проверяют Origin. Ограничитель коротких всплесков работает на экземпляре Vercel; общий суточный предел чатов — в процессе речевого шлюза. Перезапуск шлюза сбрасывает его счётчики. Это защита демонстрации, а не гарантированный финансовый лимит или полноценная учётная система.

Речевой поток использует MP3 128 кбит/с для передачи в браузер, сохраняя синтез 48 кГц и тот же мужской голос. Так уменьшается сетевой объём по сравнению с несжатым WAV. Это кодирование с потерями; идентичность исходному PCM не заявляется. Обычный WAV-endpoint сохранён для проверки распознавания. В голосовом режиме текст начинает раскрываться при запуске первого аудиофрагмента; синхронизация не сокращает время вычисления самой модели.

## Границы бесплатного размещения

- Бесплатный CPU выделяется по требованию. После простоя возможны ожидание, сон и холодный запуск. Круглосуточная доступность не гарантируется.
- Используется доступная бесплатная квота GigaChat владельца. Она может исчерпаться; автоматическое приобретение платного тарифа не настроено.
- Ссылка Production должна проверяться без авторизации Vercel. Успех защищённого Preview не доказывает публичный доступ.
- Веб-история и вложения сохраняются в браузере проверяющего. IP не используется как идентификатор. На другом устройстве история начинается пустой.
- Файловые контрольные точки, перенос папки дела, CLI и фоновый мониторинг относятся к самостоятельному запуску репозитория. Vercel не использует папку `cases` для общего хранилища. Закрытие вкладки не оставляет там работающего фонового аналитика.
- Аудио и расшифровки речевой шлюз не записывает на диск; запросы обрабатываются в памяти. Условия инфраструктурных журналов определяются провайдером размещения.

## Приёмка

`node agent/verify-cloud-stream.mjs https://decision-contour.vercel.app` проверяет публичный доступ, поток аудиофрагментов через Vercel и реальные текстовые дельты. Для этого теста ключ не нужен: он получает такой же анонимный сеанс, как браузер. Проверка использует квоту модели владельца. Готовность HTTP-потока не доказывает качество микрофона или воспроизведения на конкретном устройстве.

После сборки контейнера выполните `node agent/verify-speech.mjs <адрес/asr> <адрес/tts>` с `QWEN_VOICE_KEY` в окружении. Это тест синтезированной записи, не физического микрофона. Затем отдельно проверьте публичный сайт в браузере: новый пустой проект, текстовый вопрос, таблицу и график, изображение, ссылку, диктовку и голосовой разговор. Проверка реального микрофона и звука требует участия человека. Результаты и задержки фиксируйте отдельно от прежних локальных измерений.
